# Agent Instructions

## Source of truth

- Read `PLAN.md` before making project decisions. It is the source of truth for the portfolio's goals, scope, visual direction, and technology.
- Use `backlog.md` as the ordered checklist from setup through launch readiness.
- If an implementation detail is not settled in `PLAN.md`, choose a sensible option that fits it and record any lasting decision in `PLAN.md`.

## Project direction

- This is a professional, clean, polished portfolio for a computer science student, aimed at potential collaborators and internship teams.
- Present software engineering as the foundation, with networking experience and growing interests in data science, machine learning, and AI.
- The first release is a static Astro + TypeScript site. Do not add a backend unless the user asks to revisit that scope.
- Use placeholders for personal and project details until the user provides them. Never invent credentials, project outcomes, experience, or contact information.
- Follow the dark technical hero and light content section direction. Keep the work readable, responsive, and accessible.

## Working approach

- Work through `backlog.md` in order, keeping changes focused on the current step.
- Check off a backlog item only after its work is complete; keep the list concise and update it as progress is made.
- Prefer simple, maintainable solutions and avoid adding dependencies or features without a clear need.
- Preserve semantic HTML, keyboard access, readable contrast, and reduced-motion preferences.
- Share meaningful progress and surface decisions that materially change the agreed direction.
